Log · 제작 로그 아카이브

작업 기록은
무조건 한다.
선별은 회고가 한다.

18일 동안 334건을 적었다. 어떤 기록이 중요해질지는 적는 시점에 알 수 없기 때문에, 무엇을 남길지 고르는 일은 적을 때가 아니라 돌아볼 때 한다. 사고와 교훈만 골라 적으면 당시엔 사고인 줄 몰랐던 것이 통째로 빠진다. 아래 핀 1 「계획한 초가 전부 과대였다」가 그 사례다 — 적을 땐 컷 길이가 계획과 다르더라는 메모 한 줄이었고, 회고에서 물량을 확정하는 방식 자체를 바꾼 문장이 됐다. 선별해서 적었다면 남지 않았을 줄이다.

작업 기록은 무조건 한다 — 기록의 선별은 회고가 한다. 어떤 기록이 중요해질지는 적는 시점에 알 수 없다. 사고·교훈만 선별해 적으면 “당시엔 사고인 줄 몰랐던 것”이 빠진다(“계획 초 과대”는 적을 땐 메모였고 회고에서 핵심 문장이 됐다).

회고가 골라낸 여덟 건

334건 전부가 같은 무게는 아니다. 아래 여덟 건은 그 뒤의 판단을 바꾼 기록이다. 각 건은 무엇이 틀렸고, 무엇을 근거로 대응을 정했고, 그래서 어떤 원칙이 남았는지 순으로 적었다. 카드 끝의 “배운 것” 한 줄이 그 기록이 규율로 승격되며 남긴 문장이다.

시기 필터

필터는 이 아래 핀 8건과 페이지 하단의 릴리즈 노트 3편에 함께 걸린다. 기획(1~5일차) · 생성(6~12일차) · 편집·후반(13~18일차)은 작업 종류 기준이고, 좌우 문제(핀 4)는 한 시기에 묶이지 않아 전 기간에 모두 걸어 뒀다. 회고는 완주 이후에만 가능한 판단이라 별도 칸으로 뒀다 — 핀 8이 여기에만 있다.

전체 — 핀 8건 · 릴리즈 노트 3편 표시 중

01
생성 2026-07-29

계획한 초가 전부 과대였다

S01 첫 컷을 7초로 계획했는데 4초 생성 안에서 내용이 다 끝났다. 원장의 컷별 초 배분은 종이 위 압축에서 나온 추정치였고, 생성 결과로 검증된 적이 한 번도 없었다. 이 발견이 컷 병합 원칙(같은 화각에서 이어지는 2~3컷을 하나의 연속 테이크로)을 낳았고, S02가 즉시 6컷에서 3샷 15초로 재편됐다. 87컷 420초로 출발한 계획은 최종 38샷 179초가 됐다.

배운 것

초 단위 계획은 추정이다. 첫 생성 결과가 나오는 즉시 실측으로 캘리브레이션한다.

02
생성 2026-07-28

초벌 87장을 하루 만에 내려놓다

컷 구성 확정 직후 87컷의 첫 프레임 87장을 일괄 생성했다. 이틀 뒤, 87장 전부를 직접 쓰지 않기로 했다. 확정 시트 20장과 그 사이 확정된 컷 3장의 질감·조명이 품질 기준을 끌어올렸고, 초벌은 그 기준에 못 미쳤다. 87장은 구도 참고로만 격하됐다. 일괄 생성 자체가 낭비는 아니었다 — 방향 유효 여부를 15씬 프리뷰로 먼저 거르고, 87장으로 구도를 확정한 뒤, 품질은 컷별 개별 생성이 맡는 3단 구조가 여기서 생겼다.

배운 것

대량 생성물의 역할은 채택이 아니라 기준 발견일 수 있다. 폐기를 손실로 집계하지 않는다.

03
생성 2026-07-27

“LOCKED”라는 단어가 생성을 오염시켰다

확정 자산에 붙인 상태 라벨 LOCKED를 모델이 “이 이미지의 포즈·카메라·구도·조명을 그대로 복제하라”는 명령으로 읽었다. 새 컷들이 레퍼런스를 과도하게 복제하기 시작했다. 대응은 두 갈래 — 레퍼런스마다 역할을 선언하는 정책(캐릭터=얼굴·헤어·체형만, 배경=공간 구조만, 소품=형태·재질·색만)을 신설하고, 파일 49개의 이름에서 LOCKED를 CONFIRMED로 바꿨다. 참조 793건을 73개 파일에서 수정했고 깨진 링크는 0건이었다.

배운 것

제작 관리 용어와 모델 입력 어휘는 분리해야 한다. 상태 라벨이 프롬프트에 스며들면 명령이 된다.

04
전 기간 2026-07-25 ~ 08-07

좌우와의 전쟁

좌우는 전 기간에 걸쳐 가장 자주 틀린 축이었다. 역축 배경에서 반전 누락 2건(한 번은 통과 판정을 내렸다가 도면 표기를 화면 실측보다 우선한 것이 오류로 규명돼 정정), 특정 배경축에서 모델이 좌우를 반전 해석하는 경향 발견(의도의 정반대로 기재해야 원하는 결과가 나옴), 기상 컷에서 방향 오기 3회 연속, 클라이맥스 컷에서 미러 2연속(확정컷은 우하단을 보는데 시선 지시를 좌상단으로 임의 지정 → 모델이 모순을 인물 반전으로 해소). 대응도 단계적으로 진화했다 — 도면 교차검증, 이전 컷 프레임을 START POSE 레퍼런스로 첨부, 검수 시 정방향/미러 diff 수치 비교 상시화.

배운 것

방향 지시는 확정 프레임을 직접 보고 정한다. 프롬프트 안의 방향 모순은 미러의 가장 흔한 트리거다.

05
생성 2026-08-08

눈물을 금지하는 어휘는 없다

이별 정점 클로즈업에서 “눈물이 고이되 흐르지는 않는” 상태를 텍스트로 지시했다. 금지 어휘 5계열을 동원한 8테이크가 전부 실패했다 — 맥락이 어휘를 이긴다. 이별 씬의 클로즈업이라는 맥락 자체가 눈물을 완성시켰다. 방침을 “약간 허용”으로 바꾸고 5테이크를 전수 프레임 비교해 낙하가 가장 적은 판을 골랐다. 반대 사례도 같은 주에 나왔다 — 다른 컷에서는 모델의 “감정 아크 완성” 성향을 역이용해, 시점 배치만으로 눈물 타이밍이 정확히 걸렸다.

배운 것

모델 경향과 싸우지 않는다. 경향을 못 막을 때는 다테이크 생성 후 실측 선별로, 쓸 수 있을 때는 아군으로.

06
후반 2026-08-09 ~ 08-10

4단 보정보다 재설계 1회가 쌌다

폰 화면 부재중 배너의 작은 한글이 깨졌다. 후반 보정으로 살리려고 4단계를 올라갔다 — 정적 PNG 패치, 등속 트래킹(-5.6px/s 실측), 46프레임 개별 템플릿 매칭, 도너 영역 이식. 전부 만족스럽지 않았다. 결국 배너 설계 자체를 폐기하고 “수신 중 화면을 뒤집어 놓는” 행동으로 컷을 재생성해 종결했다. 정보를 키우는 보정이 아니라 정보를 행동으로 대체하는 설계 전환이 답이었다.

배운 것

소형 텍스트 소품은 보정 대상이 아니라 설계 대상이다. 에스컬레이션이 3단을 넘으면 설계로 돌아간다.

07
후반 2026-08-10

사람 귀를 통과한 마스터에서 816ms가 나왔다

귀와 눈으로 검수를 마친 최종 마스터를 독립 QA(별도 에이전트, 63툴/22분)에 넣었다. 구조 결함 3건이 나왔다. 가장 큰 것은 오디오 스트림 카피 병합이 이음새 37곳에서 프레임을 겹쳐 쌓은 누적 드리프트 816ms — 재생으로는 들리지 않지만 구조적으로 존재하는 결함이었다. 디지털 무음 0.604초, 블러 램프의 오프바이원 프레임 누락도 함께 나왔다. 수정은 근본 처방으로 — 38개 세그먼트를 전부 디코드해 PCM 도메인에서 정렬·병합하고 한 번만 인코딩했다. 재검증에서 드리프트 0, 스트림 길이 194.125초 정확 일치.

배운 것

사람 검수와 구조 검증은 다른 결함을 잡는다. 최종 산출물에는 반드시 둘 다 건다.

08
회고 2026-08-11

완주 다음날, 연기 문제의 절반이 대본이었음을 알았다

완성본의 대사 톤이 아쉽다는 외부 지적을 받았다. 처음엔 음성 문제로 오진해 성우 후보 10여 종과 변주, 영상 생성 음성 추출까지 시도했다. 근본 원인은 대본이었다 — 글로는 읽히지만 입으로는 나오지 않는 문어체. 대사 텍스트만 구어체로 바꾸고 나머지 전 조건을 고정한 대조 생성으로 검증했고, 결과가 뚜렷하게 달라졌다. 전체 38개 대사를 재검토하니 개정 21 / 유지 17 — 문어체 전체가 아니라 감정 정점 직전의 긴 문장만 문제였다. 이 발견은 완성 후에야 가능했다. 완주가 회고를 만들고, 회고가 다음 작품의 게이트(대사 확정 전 TTS 낭독 검사)를 만들었다.

배운 것

결함의 첫 진단을 의심한다. 변수 하나만 바꾼 대조 생성이 가장 싼 검증이다.

Release Note

파이프라인 변경 로그 3편

연재는 작품 소개가 아니라 파이프라인의 변경 로그로 쓴다. 18일을 세 구간으로 끊고, 각 편은 “무엇이 바뀌었나” 한 축으로만 진행한다. 위의 시기 필터가 이 세 편에도 그대로 걸린다.

v1

규칙이 도구를 이기게 만들기

1~5일차 · 7/24~28

기획

첫 닷새는 생성보다 체계에 썼다. 도구 규칙을 먼저 잠갔다 — 이미지는 어느 경로, 영상은 어느 표면, 생성 직전 무엇을 육안 확인하는지. 씬 프리뷰를 먼저 만들려다 순서를 정정했다. 캐릭터·배경·소품 기준 자산을 사용자 승인으로 먼저 잠그고, 씬은 그 위에서만 만든다.

검증은 처음부터 계측으로 했다. 모든 산출물에 SHA-256, 배경은 도면 교차검증, 정산표 소품은 규칙선 개수를 픽셀 y좌표로 세고 제목은 OCR로 확인, 버전 간 연속성은 SSIM. “정확히 6개” 같은 지시를 모델이 반복해서 못 지킨다는 걸 확인한 뒤로는, 자동 재생성을 중단하고 실측→사용자 결정으로 판정 구조를 바꿨다.

이 시기의 가장 큰 사건은 용어였다. 확정 자산의 상태 라벨 LOCKED가 프롬프트에 스며들며 “전부 복제하라”로 읽혔고, 레퍼런스 역할 선언 정책과 파일 49개 개명으로 대응했다. 마지막 날 15씬을 87컷 420초로 분해하고 첫 프레임 87장을 일괄 생성했다 — 이 숫자들이 다음 주에 어떻게 되는지는 v2에서.

이 시기가 남긴 것

자산 락 게이트, 역할 선언 문법, 실측 판정 원칙, 버전 불변(실패본도 보존).

v2

계획이 실측에 항복하다

6~12일차 · 7/29~8/4

생성

영상 생성이 시작되자 계획이 무너졌다 — 좋은 쪽으로. 7초로 계획한 컷이 4초에 끝났다. 컷별 초 배분 전체가 과대 추정이었다. 컷 병합 원칙이 나왔고, 생성 자원 만료 시한(영상 클립만 시한부, 이미지·편집은 이후에도 가능)에 맞춰 87컷 420초 계획을 38샷 179초 압축본으로 전환했다.

생성 경로도 바뀌었다. 브라우저 수동 생성에서 CLI로 전환해 테이크 반복을 감당했다 — 한 컷에 7테이크를 두 번 겪었다. 하나는 물리 모순(들고 있는 폰 화면이 뒤에서 점등)이 원인이라 연출 자체를 삭제했고, 하나는 좌우 방향을 텍스트로 못 잡아 이전 컷 프레임을 START POSE 이미지로 첨부하는 문법으로 해소했다. 이 시기에 굳은 원칙이 “첫 프레임 최소주의”다 — 컷 이미지는 시작 상태의 최소 조건만, 동작·사건·조명 이벤트는 전부 영상 몫. 상세한 첫 프레임이 연출을 구속한다는 걸 반복 실패로 배웠다.

12일차까지 컷 이미지 정본 44건이 완료됐고, 영상 채택이 씬 단위로 진행됐다.

이 시기가 남긴 것

실측 캘리브레이션, 컷 병합, 첫 프레임 최소주의, START POSE 문법, 모델 경향 순응 원칙.

v3

조립은 결정론으로, 검증은 이중으로

13~18일차 · 8/5~8/10

편집 · 후반

영상 완주 후 편집은 표로 했다. 산재한 편집 지시를 PRD 하나로 컴파일하고, 컷리스트 표를 ffmpeg가 읽어 트림→병합하는 결정론 조립 — 같은 입력이면 같은 출력, 수정은 표만 고쳐 재실행. 효과음은 전부 자기 촬영분에서 추출했다(무대사 컷 한정, SNR 실측, 스펙트럼 대역 검사). BGM은 없다. 현장음이 이 작품의 소리 설계다.

마지막 이틀이 이 작품의 검증 철학을 완성했다. 귀와 눈으로 통과시킨 마스터를 독립 QA에 넣자 구조 결함 3건이 나왔다 — 대표가 오디오 병합의 누적 드리프트 816ms. 최종 병합을 PCM 도메인 단일 패스로 재설계해 드리프트를 0으로 만들었다. 대사 제거 파생판에서는 광대역 음량 측정이 파찰음을 놓친다는 걸 확인하고, 통과 기준을 “레벨”에서 “ASR 재전사 + 양성 대조”로 바꿨다.

18일차에 마스터 v2(3:14, 194.125초)가 나왔다. 완주 다음날 외부 피드백에서 시작된 대조 실험이 “연기 문제의 절반은 대본”이라는 이 프로젝트 최대의 발견을 만들었고, 전 과정의 교훈은 제작 규율 38개로 정본화됐다.
