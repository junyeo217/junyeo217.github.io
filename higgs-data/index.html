Reading protocol

C · 교차 해석

숫자를 성과가 아니라 제작 행위의 흔적으로 읽는다

생성 기록은 요청과 폴더의 매핑이고, 출력 참조는 폴더가 가리키는 결과 항목이다. 둘 다 승인 샷, 최종 채택, 성공률 또는 완성 품질을 뜻하지 않는다. 이 구분을 먼저 세워야 큰 프로젝트의 물량을 작품의 우수성으로 오해하지 않고, 작은 프로젝트에서 드러난 날카로운 통제법도 놓치지 않는다.

A / RecountableA · 관찰된 사실

원자료에서 다시 셀 수 있는 층

문서 수, 바이트, 프롬프트 그룹과 텍스트 수, 생성 행, 출력 참조, 폴더, 도구 분포, 문자 수 통계는 공개 분석 JSON과 TSV의 정수 또는 그 정수로 계산한 비율이다. 이 탭의 차트는 모두 원수치를 텍스트로 다시 적어 시각화 없이도 검산할 수 있게 했다.

B / ReportedB · 팀 보고

이번 교차 차트에 넣지 않은 층

런타임, 제작 기간, 예산, 상영 결과, 특정 샷이 더 잘 작동했다는 설명은 렌더와 편집본을 독립적으로 재생 검수하지 않는 한 팀 보고다. 종합 수치가 이 층을 관찰값처럼 합산하지 않도록 규모 비교의 분모에서 제외한다.

C / SynthesisC · 교차 해석

반복 신호를 작업 규칙으로 번역하는 층

여러 프로젝트에 같은 블록이 등장하거나 서로 다른 규모에서도 같은 진단 순서가 유효할 때만 공통 원리로 올린다. 단일 프로젝트의 높은 빈도는 그 프로젝트의 제작 성격을 보여 주지만 곧바로 보편 법칙이 되지는 않는다.

D / LimitD · 검증 한계

A · 관찰된 사실

평균만 보면 숨겨지는 두 종류의 프롬프트 체계

전체 45,018개 프롬프트 텍스트의 평균은 9,548.60자, 중앙값은 8,222자다. 프로젝트별로는 ADILIADA처럼 평균 5,694.33자에 중앙값 1,686자인 긴 꼬리형 분포와, KOK_BORY처럼 평균 10,583.02자와 중앙값 10,305자가 가까운 일관형 분포가 함께 존재한다.

Long tailC · 교차 해석

평균과 중앙값의 간격은 혼합된 작업 단위를 암시한다

ADILIADA는 평균이 중앙값의 약 3.38배이고 HELL GRIND는 약 1.50배다. 짧은 지시와 긴 명세가 한 모집단에 함께 있다는 신호로 읽을 수 있다. 다만 길이만으로 블록 수나 샷 난도를 확정할 수는 없다.

ConsistencyC · 교차 해석

평균과 중앙값이 가까우면 규격화 정도를 점검한다

KOK_BORY는 평균이 중앙값보다 약 2.7% 높다. 프롬프트 길이가 비교적 한 구간에 모인 신호지만, 동일 템플릿을 썼는지 또는 내용 품질이 일정한지는 원문 블록을 별도로 확인해야 한다.

PracticeC · 교차 해석

길이 목표 대신 누락 검사를 둔다

좋은 프롬프트를 특정 문자 수로 정의하지 않는다. 현재 샷의 목표, 활성 레퍼런스 역할, 배치, 카메라, 시간 비트, 물리와 빛, 오디오, 연기, 제한 조건이 필요한 만큼 들어갔는지 점검한다. 필요 없는 블록은 길이를 채우기 위해 추가하지 않는다.

BoundaryD · 검증 한계

문자 수는 성과 지표가 아니다

긴 프롬프트가 더 정밀할 수도 있고 중복이 많을 수도 있다. 짧은 프롬프트가 역할이 명확할 수도 있고 필요한 제약이 빠졌을 수도 있다. 실제 입력 자산과 렌더를 함께 보지 않으면 길이와 성공률의 관계는 판정할 수 없다.

Conflict 01C · 교차 해석

도구 집중 vs 역할별 분산

집중: KOK_BORY는 Seedance 2.0이 97.9%다. 분산: ONEIRIC은 같은 도구가 49.4%이고 두 번째 도구가 24.1%다. 출력 형식과 반복 조건을 일정하게 유지해야 하면 집중이 유리할 수 있고, 이미지·정체성·영상 역할을 나눠야 하면 분산이 유리할 수 있다.

전환 신호: 한 도구의 실패를 프롬프트 수정으로만 반복하는지, 또는 역할별 자산 생성이 필요한지 확인한다.

Conflict 02C · 교차 해석

짧고 긴 지시의 혼합 vs 일정한 장문 규격

혼합: ADILIADA는 평균 5,694.33자지만 중앙값은 1,686자다. 규격: KOK_BORY는 평균 10,583.02자와 중앙값 10,305자가 가깝다. 상태 수정처럼 작은 요청과 전체 샷 명세가 섞이면 혼합이 자연스럽고, 반복되는 외형·제약 계약이 길게 유지되면 규격화가 자연스럽다.

전환 신호: 매 요청이 같은 필수 블록을 요구하는가, 아니면 이미 잠긴 블록에서 한 변수만 바꾸는가.

Conflict 03C · 교차 해석

행동·시간 중심 vs 스타일·락 중심

행동·시간: ZEPHYR는 행동 63.2%, 출력·시간 60.8%다. 스타일·락: KOK_BORY는 스타일 92.3%, 네거티브·락 88.5%지만 행동 6.2%, 출력·시간 1.0%다. 특수 물리의 진행을 통제하는 샷과 외형·문화적 디테일을 지키는 샷은 프롬프트의 무게중심이 반대다.

전환 신호: 실패가 “무엇이 어떻게 움직였는가”인지 “무엇처럼 보였는가”인지 먼저 분류한다.

Conflict 04C · 교차 해석

출력 다중성 vs 거의 일대일 연결

다중 연결: KOK_BORY는 생성당 출력 참조 3.872, Cully는 3.610이다. 거의 일대일: ZEPHYR는 1.010, ADILIADA는 1.673이다. 한 요청에서 여러 후보를 비교하는 구조와, 한 기록을 한 결과에 가깝게 추적하는 구조는 로그와 승인 단위가 달라야 한다.

전환 신호: 반복의 목적이 후보 폭 확보인지, 특정 결함의 전후 비교인지 정한다.

Method

분석 방법과 편집 원칙

자료의 존재를 제작 성공으로 바꾸지 않고, 재현 가능한 수치와 브리프 서술과 학습용 결론을 따로 기록했다.

  • 전수 범위

    292개 파일의 경로·형식·크기·읽기 가능 여부를 확인하고 14개 JSON, 6개 ZIP, Markdown 인코딩과 코드펜스를 검증했다.

  • 내용 중복 제거

    프로젝트 바깥과 ZIP 추출 폴더 안에 중복된 브리프·인벤토리 12개는 한 번만 읽고, `.DS_Store`는 내용 분석에서 제외했다.

  • 근거 상태

    관찰된 사실, 팀 보고, 교차 해석, 검증 한계를 시각·문구 모두로 구분했다.

  • 안전한 재서술

    권리 회피나 특정 생존 인물 모사 사례는 공개 교육 문장으로 재현하지 않고, 권리 정리된 레퍼런스와 비개인적 음향 특성으로 바꿨다.

  • 한계 보존

    프로젝트 영상·음원과 생략된 이미지가 없어 검증하지 못한 품질 주장은 각 프로젝트 마지막에 남겼다.

Reading guide

이 자료를 실제 제작에 적용할 때

공통 원리는 체크리스트로, 프로젝트별 기법은 실험 가설로 사용한다. 모델·서비스·정책은 바뀌므로 당시 우회책보다 문제를 분해한 방식을 가져가는 편이 안전하다.

Use권장

작은 파일럿으로 검증

자산·위치도·목소리·프롬프트 구조를 한 장면에서 먼저 시험하고, 실제 렌더와 재생 결과가 통과할 때 다음 장면으로 확장한다.

Avoid주의

숫자를 성공률로 읽지 않기

출력 수가 많다는 사실은 탐색 규모를 보여줄 뿐 승인 비율이나 작품 품질을 보여주지 않는다.

Record실행

변경 한 줄과 관찰 한 줄을 함께 남기기

무엇을 바꿨는지와 결과에서 무엇이 달라졌는지를 짝으로 기록해야 다음 생성이 학습이 된다.

Finish완주

프롬프트보다 실제 표면으로 끝내기

이미지·영상·오디오·편집본을 실제 크기와 재생 환경에서 보고, 정체성·연속성·소리·자막·링크를 확인한 뒤에만 완료로 올린다.
