Shared workflow

공통으로 관통하는 10단계

모든 프로젝트가 같은 순서로 움직였다는 뜻은 아니다. 여섯 사례에서 반복적으로 확인되는 일을 학습 순서로 재배열한 합성 워크플로다.

  1. 대본 스트레스 테스트목표·장애물·전술·반전·가치 변화가 장면 안에 있는지 확인하고, 생성으로 해결할 수 없는 드라마 문제를 먼저 줄인다.
  2. 자산 레지스트리인물 정체성, 상태, 의상, 위치, 소품, 음성을 이름과 버전으로 분리한다. 새 상태는 기존 파일을 덮지 않는다.
  3. 레퍼런스 역할 계약각 입력이 제공할 속성과 제공하지 않을 속성을 적는다. 현재 컷의 행동과 카메라가 참조 이미지 포즈에 끌려가지 않게 한다.
  4. 상태·각도·물리 테스트표정, 손, 의상, 다른 인물과의 접촉, 위치판을 작은 시험으로 먼저 돌려 입력이 실제 동작에서도 버티는지 본다.
  5. 공간 지도와 축마스터 와이드, 출입구·창·큰 가구 같은 앵커, 카메라가 머물 쪽, 180도 축과 인물의 앞뒤 관계를 고정한다.
  6. 샷 명세 작성맥락 → 레퍼런스 → 배치 → 렌즈·카메라 → 시간 비트 → 물리·빛 → 대사·오디오 → 연기 → 제약 순으로 한 컷의 계약을 만든다.
  7. 한 변수씩 생성작동한 블록은 유지하고 관찰된 결함 하나만 바꾼다. 파일명·폴더·설정·판정을 같은 로그에 남긴다.
  8. 정체 구간에서 샷 재설계10–20회 안팎으로 같은 실패가 반복되면 문장을 다듬는 대신 행동을 나누거나 앵글·입력·샷 길이를 바꾼다.
  9. 편집과 생성 병행완벽한 샷을 모두 기다리지 않고 조립해 빈 구간과 연속성 문제를 확인한다. 편집 결과가 다음 생성 우선순위를 결정한다.
  10. 픽처락 이후 통합클린업 → 색 통일 → 연속 앰비언스 → 음악·사운드 → 최종 재생 검수 순으로 서로 다른 생성 결과를 한 작품으로 묶는다.

Prompt anatomy

프롬프트는 분위기 문장이 아니라 촬영 명세다

아카이브 전체에서 카메라·오디오·스타일 구획이 반복된다. 가장 긴 프롬프트도 실제 실행 단위는 짧은 블록과 시간 비트로 나뉜다.

  1. Context장면의 상황과 한 컷이 서사에서 해야 할 일.
  2. Active references사용할 자산과 역할, 보존할 속성, 현재 컷에서 바꿀 속성.
  3. Geography / map인물·소품의 시작 위치, 시선 목표, 출입 축, 카메라 쪽.
  4. Format / optics비율, 초점거리 또는 FOV, 심도, 왜곡과 해상감.
  5. Camera시작 프레이밍, 이동 경로, 끝 프레이밍, 움직이지 않을 조건.
  6. Timed action짧은 현재형 문장으로 행동을 1–3초 단위의 비트로 분해.
  7. Physics / light무게, 접촉, 관성, 천·머리·입자의 반응과 하나의 광원 논리.
  8. Dialogue / audio화자, 정확한 대사, 말하지 않는 인물, 현장음, 음악 제외 조건.
  9. Acting감정 이름 대신 목표·전술·호흡·눈·몸의 작은 행동.
  10. Locks / absences원하는 결과를 긍정형으로 먼저 쓰고, 반복 실패에만 좁은 부재 조건을 더한다.

Shared techniques

카메라·연기·오디오·반복 생성의 공통 문법

프롬프트 길이보다 실패를 관찰하는 기준이 중요하다. 다음 네 묶음은 장르와 규모가 다른 프로젝트에서도 반복됐다.

01 / Space교차 해석

공간 연속성은 미리 설계한다

점유된 마스터 와이드, 눈에 띄는 앵커, 카메라 사이드와 180도 축, 위치도·색 도식·깊이 지도를 통해 역축에서도 같은 공간을 유지한다.

장소 레퍼런스는 “분위기”가 아니라 geometry와 landmark를 공급한다.

02 / Acting교차 해석

감정 대신 행동 가능한 전술

“슬퍼한다” 대신 눈을 피하고, 숨을 멈추고, 손을 바쁘게 움직이고, 상대의 반응을 기다리는 식으로 카메라가 볼 수 있는 행동을 적는다.

살아 있는 샷은 시선 변화, 호흡·깜빡임, 작은 물리 사건이 겹친다.

03 / Audio교차 해석

목소리도 반복되는 자산 계약이다

음역·음색·템포·억양 블록을 장면마다 유지하고, 발화자는 한 번에 좁히며, 침묵하는 인물과 현장음을 별도 조건으로 지정한다.

생성 클립에는 현장음 중심, 음악은 후반에서 통합하는 패턴이 우세하다.

04 / Iteration교차 해석

문장보다 샷 설계를 바꿀 때를 안다

작동한 구획은 그대로 두고 한 줄만 바꾼다. 같은 실패가 누적되면 더 긴 프롬프트가 아니라 행동 분할, 새 앵글, 다른 입력, 더 짧은 샷으로 문제를 바꾼다.

진단 없는 재생성은 기록을 늘리지만 학습은 늘리지 않는다.

Contradictions

서로 충돌하는 조언은 규칙이 아니라 맥락이다

브리프의 강한 문장을 그대로 일반화하지 않았다. 프로젝트별 우회책과 현재도 쓸 수 있는 제작 원리를 분리한다.

Negative맥락 필요

“네거티브를 쓰지 말라”는 절대 규칙이 아니다

아카이브 자체가 말하지 않기, 음악 없음, 추가 팔다리 없음 같은 좁은 부재 조건을 반복한다. 원하는 행동을 먼저 긍정형으로 쓰고, 실제 반복 실패에만 제한적으로 부재 조건을 더하는 편이 일관된다.

Age역사적 우회

나이 생략은 당시 필터 대응 사례

한 프로젝트의 나이 표기 회피 조언은 다른 프로젝트의 연령 명시 프롬프트와 충돌한다. 보편 안전 규칙이 아니라 당시 서비스 동작에 맞춘 우회로 읽어야 한다.

Voice안전한 변환

실존 인물 모사 대신 음향 특성

권리 확인된 오디오만 쓰고, 목소리는 낮은/높은 음역, 거친/맑은 음색, 빠르기, 억양, 호흡과 발화 리듬처럼 비개인적 특성으로 고정한다.

Volume편향 주의

큰 프로젝트가 반드시 보편적이지는 않다

Cully는 전체 생성 기록의 약 69.5%, 프롬프트 문자 수의 약 75.6%를 차지한다. 따라서 빈도는 그 프로젝트의 규모를 보여줄 뿐 원리의 보편성을 자동으로 증명하지 않는다.

Integrity & limits

자료 무결성과 공개 범위

모든 파일은 읽을 수 있었고 14개 JSON과 6개 ZIP 검증을 통과했다. 다만 컬렉션은 하나의 동시 스냅샷이 아니며, 프로젝트별 누락 이미지와 카운터 차이를 그대로 남긴다.

  • 형식 무결성

    265개 Markdown은 UTF-8·NUL·코드펜스 검사를 통과했고, 14개 JSON은 파싱되며, 6개 ZIP은 내부 테스트와 SHA-256 대조를 통과했다.

  • 의도적 제외

    중복된 외부/내부 브리프·인벤토리 12개와 Cully의 `.DS_Store` 2개는 분석 중복에서 제외했다. contributor handle과 계정 화면은 공개 학습 내용에 넣지 않았다.

  • 미디어 누락

    브리프 이미지 다수가 생략됐고 실제 프로젝트 MP4·오디오는 없다. ADILIADA의 UI 근거 스크린샷 5개만 이미지 파일로 존재한다.

  • 스냅샷 차이

    폴더명은 2026-08-14지만 ADILIADA 증거는 2026-08-21까지 이어진다. KOK_BORY는 공개 버전만 포함하고 미공개 작업 변경은 제외한다.

  • 카운터 차이

    여섯 프로젝트의 남은 접근 불가·오래된 카운터는 합계 73건이다. 전체 비율은 작지만 KOK_BORY 59건은 해당 프로젝트 안에서 별도 주의가 필요하다.

ADILIADA

Asset system

정체성 원본은 고정하고 상태만 수술한다

가까운 기본 초상은 얼굴 정체성의 유일한 권위로 두고, 의상·상처·대체 세계의 변화는 마스크와 포인트 편집으로 주변에 쌓는다. 상태 변형이 다시 얼굴을 해석하지 못하게 만드는 방식이다.

01관찰된 사실

원본 얼굴 픽셀을 보존하는 변형

기본 클로즈업을 다시 생성하는 대신, 옷·머리 주변·상처처럼 바뀌어야 하는 구역만 국소 편집한다. 얼굴과 표정까지 다시 그리면 세계마다 다른 배우가 되기 쉽다.

02교차 해석

상태는 정체성의 하위 버전이다

기본 인물 → 의상 상태 → 부상 상태처럼 계보를 남기되, 파생물을 다시 새 정체성 원본으로 쓰지 않는다. 어느 층이 얼굴을 책임지는지 항상 한 곳이어야 한다.

03관찰된 사실

시각 앵커와 깊이 구조

다인물·다장소 컷은 도식과 깊이 관계를 함께 써 인물의 앞뒤·시선·카메라 쪽을 고정한다. 도식은 위치를, 자산은 정체성과 재질을 책임진다.

04실습 원리

한 번에 한 상태만 바꾼다

같은 초상으로 기본 의상과 대체 의상 두 버전을 만들고, 얼굴 영역의 차이와 의상 영역의 차이를 따로 비교한다. 더 멋지게가 아니라 수정 범위를 검수한다.

CINEDANCE prompt

짧지만 역할과 시간 비트가 분명한 샷 명세

ADILIADA의 프롬프트는 전체 파이프라인 중 비교적 압축돼 있지만, 레퍼런스 역할·아이 라인·시간 세그먼트·대사와 오디오·물리와 빛·보존 조건은 빠지지 않는다.

  1. 역할 선언인물 이미지는 정체성, 공간 이미지는 구조, 위치도는 배치만 제공한다고 좁힌다.
  2. 아이 라인과 시작 배치누가 누구를 어느 높이에서 보는지, 프레임의 앞·뒤·좌·우를 먼저 고정한다.
  3. 시간 비트행동을 몇 초 단위로 나누고 각 비트에 하나의 가시적 변화만 준다.
  4. 대사와 소리화자, 대사, 비화자의 침묵, 현장음의 위치를 구분한다.
  5. 물리·빛·락접촉과 무게, 한 광원 논리, 변하지 않을 얼굴·의상·배경 요소를 마지막에 확인한다.

Post-production

생성 감독을 편집 안에 넣는다

조립이 끝난 뒤 생성 샷을 수동으로 수선하는 것이 아니라, 러프컷이 어떤 샷을 다시 만들어야 하는지 결정하는 감독 표면으로 작동한다.

  • Assembly

    사용 가능한 후보를 먼저 배치해 장면 길이와 누락된 행동을 드러낸다.

  • Rough cut

    정체성보다 편집 리듬과 인과가 무너지는 구간을 먼저 찾는다.

  • Generation supervision

    빈 칸과 연속성 오류를 새로운 생성 발주로 되돌린다.

  • Fine cut + cold viewers

    제작 맥락을 모르는 관객 반응으로 설명이 필요한 구간을 확인한다.

  • Picture lock onward

    픽처락 뒤에 클린업·색·사운드를 통합해 생성별 차이를 작품의 한 톤으로 묶는다.

Assets & states

얼굴과 몸을 한 이미지에 모두 맡기지 않는다

가까운 초상은 얼굴의 권위, 얼굴을 비운 와이드 전신 패널은 체형·의상·실루엣의 권위로 나눈다. 전신 생성에서 얼굴이 작아져 흔들리는 문제를 구조적으로 차단하는 설계다.

Portrait관찰된 사실

클로즈업이 얼굴을 공급한다

전신 패널의 얼굴 영역을 비우면 최종 컷의 얼굴 소스가 클로즈업 정체성 참조로 수렴한다. 웃음·무표정도 별도 상태로 둔다.

Body관찰된 사실

전신 패널은 중립적이어야 한다

중립광, 빈손, 읽기 쉬운 의상과 실루엣을 사용한다. 드라마틱한 포즈와 소품을 넣으면 후속 샷이 그 상태를 반복하기 쉽다.

State교차 해석

시대·의상·부상은 독립 상태

2011년이라는 시대 조건, 상처, 오염, 특정 소품은 기본 인물과 분리한다. 현대 물건으로 회귀하는 장면에서는 시대를 하드 룰로 반복한다.

Stress팀 보고

모션 스트레스 테스트를 잠금 전에 한다

다른 인물·장소와 섞은 10회 안팎의 테스트로 얼굴·몸·의상이 실제 동작에서도 버티는지 확인한 뒤 자산을 고정했다고 브리프는 설명한다.

Optics & geography

렌즈 요청이 먹히려면 입력 안에 그 화각이 있어야 한다

브리프는 10개의 FOV 앵커와 29–84° 구간을 상대적으로 안정적인 범위로 설명한다. 정확한 숫자보다 참조 이미지가 요청한 화각과 왜곡을 지지하는지가 중요하다.

  • Occupied master

    빈 장소판만으로는 인물 크기와 동선이 흔들린다. 실제 인물이 점유한 마스터 와이드로 장면의 스케일과 위치를 고정한다.

  • Stable map

    문·창·차·큰 가구 같은 랜드마크와 인물의 시작 위치를 같은 지도로 공유한다.

  • Fixed axis

    카메라가 머무는 쪽과 180도 축을 장면 단위로 고정해 역축에서 좌우 관계가 뒤집히지 않게 한다.

  • FOV anchor

    화각 숫자만 쓰지 않고 비슷한 프레이밍의 시각 앵커를 연결해 모델의 해석 범위를 좁힌다.

Acting & audio

행동 마스터와 목소리 마스터를 반복한다

시대 장편의 연속성은 얼굴만 맞는다고 끝나지 않는다. 인물이 보는 방식, 움직이는 리듬, 손의 습관, 억양을 장면마다 같은 조건으로 호출해야 한다.

Eyes관찰된 사실

눈이 장면 안에서 일하게 한다

시선 목표, 반응 지연, 깜빡임, 상대와 물체 사이의 시선 이동을 적어 인물이 정지한 초상이 되지 않게 한다.

Hands관찰된 사실

손에 작은 일을 준다

잔을 만지고, 옷자락을 누르고, 물건을 정리하는 행동이 대사 사이의 몸 리듬과 물리적 현실감을 만든다.

Voice교차 해석

권리 정리된 음성 특성만 고정한다

사투리·억양·음역·거칠기·말속도·호흡을 비개인적 특성으로 반복하고, 한 클립의 화자 수와 문장 길이를 줄인다.

Overlap관찰된 사실

반응은 대사가 끝난 뒤 시작되지 않는다

상대가 말하는 동안 듣는 표정, 호흡, 자세 변화가 이어지도록 해 대사와 연기가 순차 재생처럼 보이는 문제를 줄인다.

Iteration & post

137개 장면을 버티게 한 로그와 재설계 기준

프로젝트는 장면별 로그, 한 줄 수정, 15–20회 안팎의 정체 임계점, 편집 병행을 강조한다. 같은 프롬프트를 무한히 다듬지 않게 하는 운영 규칙이다.

  1. 장면별 로그참조, 프롬프트 버전, 생성 설정, 실패 원인, 다음 한 변수를 한곳에 남긴다.
  2. 한 줄 수정이미 통과한 렌즈·빛·목소리 블록은 유지하고 문제 구문만 바꾼다.
  3. 재설계 임계점같은 실패가 약 15–20회 반복되면 행동 분할, 앵글 변경, 새 입력으로 샷을 다시 설계한다.
  4. 병렬 편집생성과 동시에 러프컷을 업데이트해 필요한 보충 샷과 중복 생성을 구분한다.
  5. 연속 앰비언스클린업과 색 통일 뒤 장면을 관통하는 환경음을 깔아 서로 다른 생성 클립을 같은 공간으로 묶는다.

Asset contract

얼굴·몸·목소리·행동·장소를 모두 잠근다

자산은 이미지 한 장이 아니라 반복 가능한 조건 묶음이다. 중립 캐릭터 시트, 원본 질감을 보존한 포인트 편집, 상태별 파생, 목소리 문장, 행동 프로필, 장소판이 서로 다른 권위를 가진다.

  • Neutral character sheet

    얼굴 클로즈업과 얼굴을 비운 전신, 중립광과 단순 배경으로 후속 생성이 특정 감정·장면을 복제하지 않게 한다.

  • Point-change variants

    의상·상처·피·오염은 마스크 편집으로 필요한 영역만 바꾸고 이미 통과한 피부·얼굴 질감을 다시 생성하지 않는다.

  • Motion stress test

    다른 인물·장소·동작과 섞어 본 뒤 얼굴과 몸이 흔들리지 않을 때 자산을 고정한다.

  • Voice + acting lock

    목소리의 음향 특성과 인물이 목표를 추구하는 몸의 방식도 이미지와 같은 반복 자산으로 본다.

  • Three-quarter location

    미래의 카메라 각도와 보이는 랜드마크를 고려해 장소판을 만들고 하나의 광원 논리를 유지한다.

15-block shot spec

긴 프롬프트도 짧은 블록으로 움직인다

15블록 구조는 정보를 많이 넣기 위한 형식이 아니라 무엇이 실패했는지 한 구획씩 진단하기 위한 형식이다. 각 행동 문장은 현재형·단문으로 유지한다.

  1. Context + references장면 목표, 활성 자산, 각 참조가 책임질 역할을 먼저 적는다.
  2. GEO + occupied wide위치 지도, 시선 목표, 인물이 점유한 시작 와이드로 스케일을 고정한다.
  3. Camera side + axis카메라가 넘어가지 않을 쪽과 좌우 관계를 명시한다.
  4. Timed behavior짧은 현재형 행동과 1–2초 단위의 마이크로 이벤트를 이어 쓴다.
  5. Physics + light무게, 접촉, 관성, 옷감·머리 반응과 하나의 광원 논리를 쓴다.
  6. Dialogue + audio한 화자, 정확한 대사, 비화자의 침묵, 현장음, 음악 없음 조건을 분리한다.
  7. Acting + locks전술·시선·호흡을 적고 반복 실패에만 좁은 부재 조건을 더한다.

Behavior, not emotion

연기는 감정 이름을 물리로 번역하는 일

Deadline solutions

정체되면 프롬프트가 아니라 문제의 모양을 바꾼다

브리프는 10–15회 안팎의 반복 실패 뒤 샷 재설계를 권한다. 복합 동작은 이미 진행 중인 상태에서 시작하고, 전환은 모델이 추적할 물리 신호로 만든다.

  • One-line patch

    실패 원인과 관계없는 구획은 고정해 어떤 변경이 결과를 움직였는지 남긴다.

  • Start in progress

    복잡한 행동을 준비부터 완주시키지 말고 이미 시작된 상태에서 짧은 핵심 구간만 생성한다.

  • Threshold transition

    변신·통과·등장은 빛의 경계, 문턱, 가림, 크기 변화 같은 가시적 임계점과 묶는다.

  • Scale anchor

    거대한 존재는 사람·문·차량처럼 익숙한 비교물을 프레임 안에 둬 크기를 고정한다.

  • Edit alongside generation

    완성 후보를 즉시 타임라인에 넣어 필요한 샷과 버릴 샷을 편집 기준으로 판단한다.

Voice, acting & post

고정 목소리, 과업 중심 연기, 다섯 단계 편집

네 인물 대화는 누가 말하는지만 맞는 것으로 부족하다. 각 목소리 조건을 같은 문장으로 반복하고, 연기는 감정 표시가 아니라 상대에게 하는 과업과 눈의 일로 쓴다.

  • Verbatim voice block

    음역·음색·속도·억양·호흡 조건을 장면마다 같은 블록으로 붙여 음성 정체성이 문장별로 흔들리지 않게 한다.

  • Task, not display

    화내 보이려 하지 않고 상대를 설득하거나 숨기거나 떠보는 과업을 수행하게 한다.

  • Eye work

    상대, 물체, 바닥, 출입구 사이의 시선 이동이 대화의 권력 변화를 보여주게 한다.

  • Five-stage edit

    조립 → 러프컷 → 생성 감독 → 파인컷 → 픽처락을 통과한 뒤 클린업·색·사운드로 간다.

Four decisions

설명보다 입력·앵커·편집을 바꾼다

각 해법은 모델을 더 세게 지시하기보다 모델이 보는 문제의 구조를 바꾼다.

01 / Physics팀 보고

캐릭터 시트를 거꾸로 뒤집는다

인물이 천장에 매달린 역전 물리를 프롬프트로 반복 설명하는 대신, 인물 입력 자체를 거꾸로 만들어 모델이 기본 중력 방향으로 올바른 결과를 보게 했다고 브리프는 설명한다.

02 / Position관찰된 사실

메카 점프에는 위치 레이아웃

점프 전후의 상대 위치와 방향을 레이아웃 참조가 맡는다. 거대한 피사체의 정체성·재질과 배치 정보를 같은 이미지에 섞지 않는다.

03 / Camera팀 보고

구조 앵커만 두고 카메라 자유를 허용

구조대가 반드시 도달해야 할 위치와 행동만 고정하고 카메라의 세부 경로는 여러 결과에서 선택하는 방식으로 탐색 범위를 넓혔다.

04 / Edit교차 해석

강한 시퀀스를 한 번에 다 쓰지 않는다

가장 좋은 변형을 편집 곳곳에 나눠 배치해 반복되는 모티프가 마지막에 절정으로 모이게 한다. 생성 품질을 편집 구조로 확장하는 방법이다.

Practice framework

같은 실패가 세 번 보이면 입력을 다시 설계한다

ZEPHYR에서 배울 핵심은 특정 프롬프트 문장이 아니라 문제를 어디에서 해결할지 선택하는 기준이다.

  1. 실패 분류물리 방향, 상대 위치, 카메라 다양성, 편집 리듬 중 어느 층에서 실패했는지 분리한다.
  2. 입력에서 해결 가능한가첫 프레임에 보이는 물리·포즈·배치는 이미지 변형이나 레이아웃 참조로 옮긴다.
  3. 앵커만 남길 수 있는가결과를 고정할 핵심 위치·접촉·도착 조건과 탐색해도 되는 카메라 영역을 나눈다.
  4. 편집이 해결할 수 있는가한 결과에 모든 비트를 요구하지 않고 좋은 움직임을 여러 컷에 분산해 서사를 만든다.
  5. 전후 비교프롬프트를 늘린 버전과 입력을 바꾼 버전을 같은 성공 기준으로 비교해 해결 층을 기록한다.
